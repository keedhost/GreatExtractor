# Технічне завдання: `Great Extractor` — кросплатформена утиліта виявлення та екстракції вбудованих файлів

## 1. Мета проєкту

Розробити CLI/TUI-утиліту (аналог `binwalk`) мовою **Rust**, яка сканує довільний бінарний файл, знаходить вбудовані в нього файли за магічними сигнатурами, показує список знахідок (offset початку/кінця, тип, розмір, впевненість) і дозволяє екстрагувати їх на диск — окремими фрагментами або рекурсивно вглиб вкладених архівів/образів.

## 2. Технологічний стек

- **Мова:** Rust (single static binary, крос-компіляція під Windows/macOS/Linux, x86_64/ARM64).
- **Паралелізм:** `rayon` — розбиття файлу на chunks і паралельний пошук сигнатур.
- **Читання файлів:** `mmap` для файлів помірного розміру + chunked/streaming I/O з перекриттям вікон (overlap buffer, щоб не втратити сигнатуру на межі chunk'ів) для файлів у десятки-сотні ГБ.
- **TUI:** `ratatui` (або аналог) для інтерактивного режиму перегляду.

## 3. Функціональні вимоги

### 3.1 Сканування (`greatie scan <file>`)
- Пошук магічних сигнатур по всій довжині файлу (не лише на початку).
- Багатопотоковий прохід з об'єднанням/дедуплікацією знахідок на межах потокових вікон.
- Для кожної знахідки: `offset_start`, `offset_end` (якщо визначено), `format`, `description`, `confidence` (0–100%), `size`.

### 3.2 Перегляд списку
- Вивід у трьох форматах: **людино-читабельна таблиця**, **JSON**, **CSV** (прапорець `--format table|json|csv`).
- Сортування/фільтрація за типом, offset, впевненістю.
- **Інтерактивний TUI-режим** (`greatie tui <file>`): навігація по списку знахідок, hex-перегляд ділянки, вибіркова екстракція окремих записів, підсвітка ентропійних зон, перемикання тем оформлення (за зразком Midnight Commander) зі збереженням вибору в `~/.GreatExtractor/config.yaml`.

### 3.3 Екстракція (`greatie extract <file>`)
- **Raw carve**: копіювання байтового діапазону `[start, end]` знайденого фрагмента в окремий файл у вихідній директорії. Без розпакування вмісту контейнерів (ZIP/GZIP/TAR залишаються стиснутими файлами як є) — це свідомо спрощений MVP-обсяг.
- **Рекурсивна екстракція** (`--recursive` / `-M`, за замовчуванням увімкнена): кожен витягнутий фрагмент повторно скановується на предмет вкладених знахідок, з обмеженням глибини (`--max-depth`, за замовчуванням, напр., 8) і захистом від циклів/вибухового розростання (ліміт на кількість витягнутих файлів, попередження при перевищенні).
- Іменування вихідних файлів: `<offset_hex>_<format>.<ext>`, вкладені рівні — у піддиректоріях за схемою `<parent>_extracted/`.
- Прапорець `--dry-run` — показати, що було б екстраговано, без запису на диск.

### 3.4 Аналіз ентропії (`--entropy` / окрема підкоманда `greatie entropy <file>`)
- Ковзне вікно ентропії Шеннона по файлу для виявлення стиснених/зашифрованих ділянок без відомої сигнатури.
- Вивід графіка ентропії (у TUI — текстовий/ASCII-графік; у CLI — таблиця/JSON з блоками offset↔ентропія).
- Позначення "підозрілих" високоентропійних ділянок у загальному списку знахідок як окремої категорії (`type: high_entropy_region`).

## 4. База сигнатур

- **Джерело:** порт бази `file(1)`/`libmagic` (BSD-ліцензія — дотримуємось умов атрибуції в `LICENSE-THIRD-PARTY`).
- Власний формат опису сигнатур у Rust (структуровані записи: magic bytes, offset, маска, опис, посилання на опційний структурний валідатор), а не повний DSL-інтерпретатор magic-файлів — це компроміс між покриттям і складністю реалізації.
- Сигнатури мають бути винесені в окремі дані (embedded resource або зовнішній файл), щоб їх можна було доповнювати без перекомпіляції рушія пошуку.

## 5. Визначення меж файлів — гібридний підхід

- **Базовий рівень (усі сигнатури):** евристика — за сигнатурою кінця (якщо є в базі) або до наступної знайденої сигнатури/кінця файлу.
- **Точний рівень (пріоритетні формати):** написати структурні валідатори/парсери, які дають точний розмір і одночасно підвищують `confidence`:
  - ZIP (парсинг End of Central Directory)
  - GZIP (trailer з CRC32 + ISIZE)
  - PNG (до чанка IEND)
  - JPEG (до маркера FFD9)
  - TAR (парсинг заголовків блоків)
  - ELF / PE (парсинг section/program headers)
  - PDF (до `%%EOF`)
- Формат без структурного валідатора отримує нижчий `confidence` і межі за евристикою.

## 6. Продуктивність

- Багатопотокове сканування (`rayon`) з налаштовуваною кількістю потоків (`--threads`).
- Обробка файлів розміром у сотні ГБ без повного завантаження в пам'ять — chunked reading з перекриттям вікон на межах (розмір вікна ≥ найдовша сигнатура в базі).
- Прогрес-бар/індикатор ходу сканування для довгих операцій.

## 7. CLI — орієнтовний перелік команд

```
greatie scan <file> [--format table|json|csv] [--min-confidence N] [--threads N]
greatie extract <file> [--output DIR] [--recursive] [--max-depth N] [--dry-run]
greatie entropy <file> [--window N] [--format table|json]
greatie tui <file>
```

## 8. Дистрибуція

- Публікація на **crates.io** (`cargo install great-extractor`, виконуваний файл — `greatie`).
- Крос-компільовані бінарники на **GitHub Releases** (Windows/macOS/Linux × x86_64/ARM64).
- За можливості — пакунки для Homebrew/Scoop/apt (може бути окремим етапом після стабілізації MVP).

## 9. Поза межами (Non-goals) для MVP

- Розпакування вмісту контейнерів під час екстракції (тільки raw carve).
- Розшифрування зашифрованих/запаролених архівів.
- Повна сумісність із синтаксисом magic-файлів `file(1)` (тільки портовані сигнатури найпоширеніших форматів).
- GUI-застосунок (лише CLI + TUI).

## 10. Пропоновані етапи розробки

1. **Ядро:** модель сигнатур + однопотоковий сканер + CLI `scan` з table/JSON/CSV виводом.
2. **Продуктивність:** багатопотоковість, chunked I/O для великих файлів.
3. **Точні межі:** структурні валідатори для пріоритетних форматів (ZIP, GZIP, PNG, JPEG, TAR, ELF, PE, PDF) + confidence scoring.
4. **Екстракція:** raw carve + рекурсія з обмеженням глибини.
5. **Ентропія:** обчислення + інтеграція у вивід.
6. **TUI:** інтерактивний перегляд/екстракція/hex-view.
7. **Дистрибуція:** crates.io, GitHub Releases, крос-компіляція, тестовий корпус файлів (штучно "склеєні" мультиформатні зразки) + CI на трьох ОС.
